# BM25 floor (EV-5b) on the three frozen benchmark sets, 2026-11-10

**Integrity note (read first).** These numbers are a plain lexical BM25 over stored chunk text. They are NOT the
system's retrieval output. The house rule "no ground-truth item edited after seeing retrieval output" concerns the
system under test; BM25 is not the system. **No fixture was changed in response to these numbers, and none may be**:
the fixtures were hash-checked before the runs (`eval_protocol_tools.py check-hash`: OK, 3 fixtures) and are only
read. `focus_gt.json` (under repair) was not run. Sets are never averaged together; every rate is `hits/n`.

## What was run

`scripts/bm25_floor.py` (EV-15), CPU only, standard library plus repo helpers, DBs opened `mode=ro`.
Okapi BM25, k1 = 1.2, b = 0.75, idf = ln(1 + (N - df + 0.5)/(df + 0.5)); tokens = lowercase `[a-z0-9]+` minus
`eval_protocol_tools.STOP` (the protocol's list); distinct query terms; query = `question_text` as written; **no
ligature repair** (naive floor: ligature-damaged words stay damaged). Documents = every stored `chunks.text`
(`title\nsection_path\n\nbody`). Hit rules are `app.retrieval_eval.score_question` (paper: gold paper in top-10;
anchor passage: anchor block id == `gold_block_id`); the report is built by `retrieval_eval.build_report`, so
`eval_strata_report.py` consumed it unchanged (member-passage columns come from it).

Index strategy: exact two-stage. One streaming pass over all chunks tokenizes each one, keeps `|d|`, and keeps
postings (`array`) only for terms occurring in the questions; scores need nothing else (N, avgdl, df of query terms).
Identical to a full inverted index, at 250-280 MB instead of GBs.

## Standard vs body-only: how much of recall is the title header

Dropping the `title\nsection_path` header costs paper R@10 0.000 (standards), 0.033 (papers, 60 -> 58),
0.073 (books, 64 -> 59) and chunk@10 0.042 / 0.066 / 0.072 (4, 4, 5 items); standards P@1 loses most on
definition-lookup (anchor P@1 1/12 -> 0/12) and paper P@1 (definition 6/12 -> 4/12). So paper-level recall is not
driven by the header on standards (the questions name the document, and the body text carries the same words), but the header carries a few points of passage recall everywhere and a lot of rank-1 precision on papers
(chunk@1 33/61 -> 24/61). Title ablation of the QUESTION is the bigger lever on paper recall (0.979 -> 0.872,
0.984 -> 0.869, 0.928 -> 0.812), against RV-3's crude ablation: 0.87 standards (matches), 0.83 books (0.812 here), 0.82 papers (0.869 here; the committed helper removes fewer words).

## Reading the floor

- **Reproduction check against RV-3 (scratch).** Standards paper R@10 0.979 (RV-3 0.98) and chunk@10 0.638 (0.63)
  reproduce. **chunk@1 does not: 25/94 = 0.266 vs RV-3's 0.23 (about 3 items)**; removing the stopword list gives
  24/94, so the gap is not the stopwords; likely tie-breaking/tokenizer details of the scratch script, which is not
  committed. Per-stratum chunk@10 agrees within 1-2 items (book-passage 0.346 vs 0.38, definition 0.500 vs 0.42,
  table 0.750, clause 0.889, guidance 0.929, edition 0.000). Papers: 0.984 / 0.852 / @1 0.541 vs RV-3 0.98 / 0.85 /
  0.52; books: paper R@10 0.928 vs 0.96 (64 vs 66 of 69), chunk@10 0.783 vs 0.80, @1 0.391 vs 0.39. The committed
  definition is this script's; the protocols' RV-3 figures stay labelled as the scratch run.
- **A lexical floor that rewards wording close to the passage.** Questions here are ~25 words, LLM-authored from the
  passage (RV-3 F-1.6), so they share rare tokens with the gold chunk: plain BM25 already finds the exact gold chunk
  in the top 10 for 0.64 (standards), 0.85 (papers), 0.78 (books) of items. Headroom for any semantic system is
  therefore small on papers `numeric-result` (16/16), `method-detail` (17/20), and standards clause/guidance; those
  strata can show a loss but hardly a gain. Only standards book-passage / definition / table / edition, papers
  equation-context and books book-passage retain real headroom.
- **Difficulty labels do not track lexical difficulty.** Standards chunk@10 falls with difficulty (0.72 / 0.63 / 0.56)
  but on papers `medium` is easiest and on books `hard` (0.793) is not harder than `easy`/`medium`; all cells are
  n = 9-51, so one item is 2-11 points. Labels are authored, not retrieved against, and say little about what a
  lexical or dense retriever finds hard.
- **Not shown.** Nothing here predicts the system's score, the sparse arm's, or a dense/reranked arm's; BM25 here
  skips ligature repair, stub handling and the system's chunk scoping; paper R@10 is near saturation and unusable as a
  headline. title_leak is not computed. The member-passage rule is `eval_strata_report`'s (an over-estimate where
  chunks share an anchor).
