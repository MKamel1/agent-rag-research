1. The three new sets are already lexically near-saturated at paper level (plain BM25: paper R@10 0.98 standards / 0.96 books / 0.98 papers); only passage level and a few strata have headroom, and nothing is written down yet (metric, ceiling, decision rule, falsifier, fixture hash) — and `run_baseline.sh` re-runs `merge_gt.py`, rewriting the fixture at measurement time.

### F-1.1 No regression gate exists; the one "runner" is Waymo-only and compares to nothing (severity: high)
- Evidence: `scripts/nb_eval_runner.py:58-64` hard-codes `FIXTURES` = (`gt_wmr`, `waymo_gt_verified`), `DEFAULT_CONFIG=.../waymo/data/config.yaml`, `DEFAULT_COLLECTION="waymo_av_safety"`; one `--collection` for all fixtures; no `--db-path/--blob-dir` forwarded (`fixture_argv`, lines 87-113). The new standards set has `run_baseline.sh` (standards only, 5 configs, no comparison); the books and papers sets have no runner at all. [VERIFIED]
- Impact: any chunker/ingest change (CQ-1..5, standards re-chunk) can regress a corpus nobody re-measures; today one person must remember which of ~8 invocations to run with which `--collection`.
- Checklist dimension: 7 (process) / 4 (change-friendliness).
- Proposed change: smallest design = a manifest (YAML or a dict in `nb_eval_runner.py`) `corpus -> {config, db, blobs, collection, fixtures[]}` replacing the `FIXTURES` tuple, plus `--baseline <combined.json>` and `--fail-on-regress`. Store baselines under `docs/eval-reports/data/baselines/<corpus>-<fixture>.json`. One command: `python scripts/nb_eval_runner.py --all --baseline-dir ...`. ~120 lines plus the existing pure-function tests in `scripts/test_nb_eval_runner.py`.
- Needs: GPU yes (to run); foundation-protected path no (`scripts/`); operator sign-off only for the tolerance rule; re-embed no.

### F-1.5 The scorer is chunk-identity: it ignores alternative gold chunks, and it makes the sets non-comparable across a re-chunk (severity: high)
- Evidence: `load_questions` (`app/retrieval_eval.py:232-300`) reads `gold_block_id`, `additional_gold_paper_ids`, `supporting_passages`; it never reads `alternative_gold_chunk_ids`. Items with alternatives: papers 8/61 (13%), books 4/69 (6%), standards 1/94 — all found by cross-verifiers reading neighbours (`papers-passage-gt/crossverify/report.md`: e.g. Q-PF-F-007's abstract chunk c4 states the same kappa). Cross-verify-2 also lists three more same-document duplicates only as "survive" notes (Q-STD-D-014 c210, D-027 c49, D-028 c58/c347) that were NOT recorded as alternatives. Q-STD-C-002 and A-018 had the duplicate in another *document* (superseded AVSC, ISO 26262-12), handled via `additional_gold_paper_ids` — which helps paper-level only; passage-level has a single `gold_block_id`. `gold_block_id` here is the gold chunk's anchor block: `excerpt_block_id != gold_block_id` for 63/94 standards (67%), 62/69 books (90%), 58/61 papers (95%) — these are not anchor luck for the exact gold chunk (hit iff that chunk is returned; I verified `n_chunks_containing_excerpt == 1` for every item and that 5 of 119 gold anchors are shared by a sibling chunk, i.e. 4% lenient false hits), but the score is chunk identity: gold ids move on any re-chunk. `excerpt_block_id` is null for 8 + 7 + 1 = 16 items (excerpt spans blocks), so even the "stable" id is missing for them. The re-grounding path (`gt_tools.ground`, merge_gt.py) recomputes ids from the excerpt text: it takes `hits[0]` in DB order although its docstring says "best first"; any excerpt that now straddles a new chunk boundary fails verification, and `merge_gt.py` then aborts the whole merge ("verification failed -- nothing merged"). The standards chunker commits are on this branch, so this will trigger for the standards DB. [VERIFIED]
- Impact: passage hit@10 is under-counted by up to ~13% of items on the papers set (a correct answer from c4 vs gold c58 scores a miss); results before and after a re-chunk are different instruments, so "did the standards chunker help?" cannot be answered with the stored gold ids; one broken item blocks re-grounding of 128.
- Checklist dimension: 5 (contract), 3 (coupling to chunk boundaries).
- Proposed change: add an additive passage metric, `passage_excerpt_hit`: hit iff a returned result's `passage_text` contains the normalised `passage_excerpt` (reuse `retrieval_eval._normalized`; `GroundedResult.passage_text` already exists, `contracts/retriever.py:37`), with `alternative_gold_chunk_ids` resolved to extra accepted excerpts/anchors in `gt_tools`. Keep the anchor-equality metric unchanged (the Waymo frozen `scoring_rule` must not change) and stamp the new rule in `scoring_rule`. This is chunker-independent: the same fixture is valid across the standards re-chunk. Make `merge_gt` per-item tolerant: report orphaned items and write the rest, failing only above a stated percentage. Record the three note-only duplicates as alternatives before freezing.
- Needs: GPU no; foundation-protected no (`app/retrieval_eval.py` + `gt_tools.py`; the fixtures stay outside `fixtures/eval/` until promoted); sign-off yes if the headline definition changes; re-embed no.
- How to verify: unit test with `FakeRetriever` returning gold's alternative chunk (hit under excerpt rule, miss under anchor rule); run `merge_gt.py` in dry-run on a copy of the standards DB after the new chunker: expected orphan count printed, nothing written.

### F-1.13 Saturated 210-question paper recall: still a useful tripwire, a poor decision instrument (severity: low)
