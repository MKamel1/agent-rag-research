# RV-4 — MCP tool surface against the product's intent

Scope reviewed: `rag/mcp_server.py`, `app/serve.py`, `rag/method_aliases.py`, `contracts/mcp_server.py`,
`contracts/retriever.py`, `app/usage_log.py`, `app/mcp_verify_client.py`, their tests, and the five
`mcp_usage.db` logs (read-only; 1,198 calls: main 24, Waymo 646, standards 390, Motional 120, Waabi 18).
Representative queries below are the operator's own — do not copy outside this file.

## Summary
1. The cross-encoder relevance score is thrown away (`Reranker.rerank` returns order only; `GroundedResult.score` is the pre-rerank RRF score) and the NB-D3 "no separation" census never tested it. The "cannot abstain" verdict is a verdict about RRF scores. The smallest honest absence step is to measure the reranker score on the new standards GT (22 absent/partial-absent items) before anything else.
2. A cold agent sees much less than the docstrings promise: no server `instructions`, zero field descriptions in the `SearchFilters` schema, the doc_type/author_org guidance lives only in `McpServer` docstrings that FastMCP never exposes, and nothing says which corpus or what documents it holds.
3. Silent empties: `filters.paper_id` with an unknown or wrong-form id returns `[]` with no error (standards log ids 327/328) while `get_paper` raises for the same id. Telemetry is blind on exactly the tools agents lean on for enumeration (213 scan calls, zero patterns logged).
4. Payload: 57% of a standards `semantic_search` response (k=10 is about 4.2k tokens) is envelope rather than passage; a Waymo call averages about 10.8k tokens. `search_papers` ships every paper's full `section_paths` (median 819 tokens, max about 45k).
5. Evidence-ranked unbuilt items: MCP-E3 (reframed as envelope slimming) > MCP-E5 (measure reranker score first) > MCP-E1 > MCP-E4 (2 `scan_methods` calls in 1,198).

## Findings

### F-4.1 The reranker score is discarded, and the abstention census never tested it (severity: high)
- Evidence: `rag/retriever.py:202-300` builds `scores = {hit.id: hit.score}` from `hybrid_search` and writes `GroundedResult(score=scores[candidate.id])` at line ~273 after the reranker has only reordered. `rag/reranker.py:164-245` returns `list[RerankCandidate]` ordered by cross-encoder score and drops the score (its own comment says "Cross-encoder scores are absolute per-(query, document) relevance values"). `Hit.score` is "the fused RRF score" (`contracts/vector_index.py:27`). RRF scores are rank-derived and bounded (`1/(60+rank)` terms), so they cannot carry absolute relevance. `docs/eval-reports/2026-08-25-nb-d3-abstention-census.md` §1 lists 17 features: per-arm rank-1 scores, gaps, Jaccards, distinct-paper counts, query length — grep finds "rerank" only in the staleness banner (lines 3, 7). The cross-encoder score was never a candidate feature. [VERIFIED by reading code and grepping the census.]
- Impact: the docstrings (`serve.py`, `mcp_server.py`) and BACKLOG MCP-E5 state that answerable and absent score distributions "do not separate, any threshold is a guess". That is true of RRF/dense/sparse scores; it is unproven for the one score that is an absolute pairwise relevance judgement. Consequence today: results are ordered by cross-encoder but `score` is not monotone in result order, so a caller who sorts or thresholds on `score` reorders by the wrong thing. 0 of 318 Waymo semantic calls returned an empty set; every absent query gets a confident full page.
- Checklist dimension: 3 (information hiding: the one number that matters is hidden inside the reranker) and 5/6 (honesty of the contract).
- Proposed change: Step 1 (free, `rag/` + an `app/exp_*` script): add a scored variant on the concrete reranker (e.g. `rerank_scored()` returning `(candidate, score)`; `Reranker`'s method is not a frozen contract, only the shapes in `contracts/retriever.py` are) and rerun the NB-D3 census scripts (§5 of that report) adding `top_rerank_score`, `rank1-rank2 rerank gap`, `count above x% of rank-1`, on (a) the new standards GT (`docs/eval-reports/data/2026-11-10-standards-gt/standards_gt.json`: 9 `absent` + 13 `partial-absent` vs 106 answerable, runner `run_baseline.sh`/`analyze_run.py` already exist) and (b) the two Waymo fixtures (12 and 14 absent). Step 2, only if AUROC is clearly above chance on both corpora: expose it. Step 3 (protected) populate `GroundedResult.metadata["rerank_score"]` (the contract comment says populating `metadata` is a T-F7 change); do not repurpose `score`, which the eval harness and NB-D3 records read as RRF.
- Needs: GPU yes (census run; fold into the pending standards GT run); foundation-protected path / sign-off: step 3 only (`metadata` population); re-embed: no.
- How to verify: AUROC of `top_rerank_score` for absent vs answerable with a bootstrap CI that excludes 0.5 on standards (22 vs 106) and on each Waymo fixture. Pass = CI lower bound above 0.65 on at least two of three sets; fail = record the null and amend the MCP-E5 row to say the reranker score was tested.

### F-4.6 Response payload: more than half is envelope, and `search_papers` ships every section path (severity: medium)
- Evidence: I built real `SearchResponse` JSON from 400 random chunks (length >= 150 chars) of each DB with `contracts` models and counted `cl100k` tokens (tiktoken). - Impact: agents already adapt by lowering `k` (standards p50 k=4-6 interactively) and calling `get_span`, so cost is paid in lost recall and context. A frozen envelope was knowingly traded for tokens in ADR-16's risk note ("mitigate: compact fields").

- Needs: GPU no; protected: yes for anything that changes `PaperSummaryView`/`GroundedResult`; the `serve.py`-level projection does not; re-embed no.
- How to verify: rerun my measurement on the projected output. Pass = standards k=10 response at most 3.1k tokens (-25%) with identical `passage_text`/`citation` content; `get_span(anchor)` still round-trips.

### F-4.9 Errors and latency read poorly to an agent (severity: low)

## Things that are good and should not be changed
1. `ScanResponse` carries `papers_scanned`/`papers_matched`/`truncated` and `section_path` on every match: it makes enumeration completeness checkable by the caller, which is ADR-16's coverage idea implemented where it matters. Agents use it (213 calls).
2. The absence-honesty language ("no relevance floor, a full page is not an endorsement", pointing to RI-M7) is true in practice (no empties, full pages) and keeps the caller the reasoner (§11A). Keep it; fix only what F-4.1 shows is untested.
3. `record_usage`: never raises, observes and re-raises, separate `mcp_usage.db` with `CREATE TABLE IF NOT EXISTS`, `functools.wraps` pinned by a test. It produced everything in this review; extend it (F-4.5) rather than replace it.
4. Fail-loud startup (`--data-dir` with a missing db exits non-zero), the `[_MIN_K, _MAX_K]` clamp, and the corpus label on errors came from real incidents (2026-08-23 session); they work.
5. `get_span` plus `Anchor` as a block-level verification round trip: it is cheap (0 ms), used in 7-15% of calls as a habit, and `mcp_verify_client.py` exercises the real stdio path; keep the contract as is.
